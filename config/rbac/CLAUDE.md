# RBAC guard rules

## OwnNamespace RBAC split

This operator uses an **OwnNamespace** install model with two ClusterRoles:

- **`role.yaml`** (generated by `controller-gen` from `+kubebuilder:rbac` markers)
  — bound via a namespace-scoped **RoleBinding**. Must contain only
  namespace-scoped resources.
- **`cluster_access_role.yaml`** (hand-maintained) — bound via a
  **ClusterRoleBinding**. Contains cluster-scoped resources only.

## When editing `+kubebuilder:rbac` markers or files in this directory

1. Run `make manifests` to regenerate `role.yaml`.
2. Verify `role.yaml` has **no cluster-scoped resources**:

```bash
grep -E 'consolelinks|clusterroles|clusterrolebindings|ingresses|storageclasses|noobaa-admin' config/rbac/role.yaml
```

This must return nothing. If it does, the marker belongs in
`cluster_access_role.yaml` instead, not in a `+kubebuilder:rbac` annotation.

CI also locks this via `TestManagerRole_NoClusterScopedResources` in
`internal/controller/rbac_manifest_test.go`.
