## Description

**Beta (early September):** Cost Management (Koku stack) only. ROS OCP and Kruize are **not** required for beta.

### Problem

Today the operator always deploys ROS and Kruize together with Cost: ROS migration runs in the schema stage, ROS/Kruize workloads are applied unconditionally, and Validation requires `ros-user` / `ros-password` on external DB secrets. Docs and gap analysis often treat “ROS/Kruize” as one unit, which hides different enablement, secret, migrate, and readiness rules.

On SaaS we ship Koku and ROS OCP together. On-prem resources are tighter: some users want **Cost only**, some want **ROS** (and typically Kruize), and some want **both**. It must also be possible to add the missing component later (day-2 enable).

If separate ROS OCP Service Operator and Koku Service Operators would be easier than flags on one CR, that is an acceptable design outcome — decide and document.

### Goals

1. **Decouple Cost, ROS, and Kruize in product language and operator behavior** — do not treat ROS and Kruize as a single inseparable blob (even if Kruize usually ships with ROS).
2. **Component optionality:** install Cost, ROS, Kruize (as product allows), or combinations; support enabling a second component after initial install.
3. **Beta posture:** Cost-only install reaches honest Ready/Available without depending on ROS migrate success or ROS/Kruize readiness. When ROS/Kruize are disabled, do not require their DB secret keys or run their Jobs/Deployments.
4. **Own deferred gap work** that only exists to harden or gate ROS/Kruize (see below). Core Cost gaps stay on their original COST-7678–7692 tickets.

### Acceptance criteria (draft)

- [ ] Spec (or equivalent) can enable/disable **Cost**, **ROS**, and **Kruize** independently (or document an explicit dependency, e.g. Kruize requires ROS, without coupling either to Cost).
- [ ] Cost-only path: no `ROSMigrationJob`; `SchemaUpToDate` does not wait on ROS; no ROS/Kruize Deployments/CronJobs/ClusterRoles applied; Validation does not require `ros-*` / `kruize-*` secret keys.
- [ ] ROS-enabled path: ROS migrate + ROS workloads + `ros-*` secret validation as needed.
- [ ] Kruize-enabled path: Kruize resources + `kruize-user` / `kruize-password` validation when required; do not imply Cost or ROS are enabled unless documented.
- [ ] Day-2: enabling a previously disabled component reconciles it without reinstalling the whole stack.
- [ ] Docs/samples state beta = Cost only; ROS and Kruize are optional / later.
- [ ] Gap-analysis items listed under “Owned gaps” closed or explicitly superseded here.
