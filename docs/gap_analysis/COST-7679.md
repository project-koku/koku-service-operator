# COST-7679 Gap Analysis: Create sample CRs and generate manifests

**Jira:** [COST-7679](https://redhat.atlassian.net/browse/COST-7679)
**Audited:** 2026-08-10
**Purpose:** Handoff audit of sample CRs and generated manifests vs ticket acceptance criteria. This document does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)); optional install → [COST-8054](../jira/COST-8054.md). Minimal/BYOI samples need not demonstrate ROS or Kruize; call them unsupported (or omit) in beta docs.

## Verdict

COST-7679 is **not done**. Generated CRD YAML and CRC install docs exist, and there are useful bundled + BYOI samples beyond the ticket’s two-CR framing — but the acceptance criteria for a **minimal** required-fields sample and a **production/HA** sample (HA profile + resource overrides + monitoring) are unmet. “CR validation works” cannot be closed while CEL/OpenAPI rules from COST-7678 are still absent.

## Remaining gaps (ticket-scoped)

### G1. Minimal sample CR — missing

Jira asks for a CR with **only required fields**. No such file exists.

What exists instead:

- Bundled sample: large surface (images, replicas, celery workers, auth, UI, monitoring)
- BYOI samples: full external connection surface + app replicas

What the CRD actually requires at top-level `spec`: **nothing**. An empty `spec: {}` is schema-valid today. Nested `required` only kicks in when parent objects are present (e.g. `kafka.bootstrapServers` if `kafka` is set; `ImageSpec.repository`/`tag` if an image object is set).

Until COST-7678 adds real required/CEL rules, a “minimal” sample should still exist as the smallest **operationally useful** BYOI (or schema-minimal) example, clearly labeled — not a full replica of the CRC bundled CR.

### G2. Production / HA sample — missing (partial overlap only)

Jira production sample must include:

| Requirement | Status in samples |
|-------------|-------------------|
| `spec.profile: ha` | **Absent** — no sample sets `profile` (API default `standard` in types/CRD) |
| Resource overrides (`*.resources.requests` / `limits` on CMSC components) | **Absent** on all CMSC samples; CPU/memory only on BYOI **infra fixture** pods (PG/Valkey/MinIO/etc.) |
| `monitoring.enabled: true` | Present on bundled + BYOI **template**; BYOI fixture app CR has `enabled: false` |

Closest stand-ins are the BYOI template (production topology intent) and bundled sample (monitoring on) — neither is an HA production profile sample.

### G3. CR validation verification — blocked / not done

Ticket: “CR validation works” after CRD install on OCP 4.20+.

| Check | Status |
|-------|--------|
| CRD `oc apply` on CRC | Documented; claimed in `docs/tasks.md` |
| Automated OCP 4.20+ install | **Missing** (CI Kind `make install` ≠ OCP 4.20) |
| CEL / `x-kubernetes-validations` exercised | **Impossible today** — no `XValidation` markers in `api/` or CRD YAML (see COST-7678 G2) |
| Admission webhook validation | **Missing** (COST-7678 G1) |

`docs/tasks.md` note “CEL validation verified” missing is correct as a gap, but the root cause is COST-7678, not a missing sample file.

### G4. OCP 4.20+ verification evidence — weak

Acceptance names OCP 4.20+. Repo evidence is CRC-oriented docs/scripts only. No workflow or test asserts apply + validation against 4.20. Closing this AC needs either:

- recorded manual verification notes (cluster version + commands + results), or
- CI / OpenShift CI job that installs the CRD and applies valid/invalid samples.

## Recommended closure order

For the team member closing COST-7679:

1. **Add a true minimal sample** under `config/samples/` (smallest useful BYOI or schema-minimal CR) and wire it into `config/samples/kustomization.yaml`.
2. **Add a production/HA sample** with `profile: ha`, explicit component `resources` overrides, and `monitoring.enabled: true` (BYOI topology — not bundled DB/cache).
3. **Delete or stop applying the legacy CRD** (`costmanagement-service-cfg.openshift.io_…`); point CRC docs/scripts at the canonical base or `make install`.
4. **Record or automate OCP 4.20+ CRD install** (version + apply + describe).
5. **Defer “CEL validation verified”** until COST-7678 lands rules; then add a short invalid-CR denial check (manual note or CI) and only then flip that tasks.md checkbox.
