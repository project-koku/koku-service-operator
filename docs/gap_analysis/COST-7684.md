## Done (meets or supersedes ticket intent)

Implemented primarily in [`internal/controller/validation.go`](../../internal/controller/validation.go) (+ [`validation_s3.go`](../../internal/controller/validation_s3.go)), invoked as stage 3 in `reconcile()` after Infrastructure and before Migration:

### Connectivity probes

- External DB TCP probe when `database.deploy=false` → `DatabaseReady` True/False (`DatabaseReachable` / `DatabaseUnreachable`)
- External Cache TCP probe when `cache.deploy=false` → `CacheReady`
- Kafka TCP probe over comma-separated `bootstrapServers` (`kafkaTCPProbe`, first reachable broker wins) → `KafkaReady`
- OIDC `jwksProbe` to `resources.KeycloakJWKSURL(cfg)` when `auth.keycloak.url` is set → `AuthenticationReady` (`OIDCReachable` / `OIDCUnreachable`). Requires HTTP 2xx and JSON with a non-empty `keys` array; uses the reconcile context; honors `insecureSkipVerify`
- S3 `ListBuckets` (AWS SDK, path-style, custom endpoint) after Secret keys pass → `StorageReady` (`StorageReachable` / `StorageUnreachable`). User `objectStorage.secretName` or Discovery’s OBC/NooBaa secret

### Secret key validation

`checkSecretKeys` requires Secret exists and listed keys are non-empty:

| Ref | Required keys |
|-----|---------------|
| `database.secretName` | Always: `koku-user`, `koku-password`, `rbac-user`, `rbac-password`. When `ros.enabled`: also `ros-user`, `ros-password`, `kruize-user`, `kruize-password`. `postgres-*` is not required on BYOI Secrets. |
| `cache.auth.secretName` | `redis-password` |
| `kafka.sasl.existingSecret` | `username`, `password` |
| `objectStorage.secretName` (or discovered S3 secret) | `access-key`, `secret-key` — fail `StorageSecretInvalid` before `ListBuckets` |

### Pipeline gating

- DB / Cache failures set `allReady=false` and return `RequeueAfter` (blocks Migration+)
- Kafka / OIDC / S3 failures set conditions only (non-blocking) — documented in function comment
- Bundled DB/Cache (`deploy=true`) skips external probes (infra readiness handled earlier)

### Env wiring for later phases

Resolved secret *names* are consumed via `EnvFromSecret` / `EnvFromSecretOptional` in [`internal/resources/env.go`](../../internal/resources/env.go) and related builders — credentials are not copied into CR status (better than the ticket’s implied in-memory resolution).

### Tests

[`validation_test.go`](../../internal/controller/validation_test.go): TCP/Kafka/`jwksProbe` (2xx+keys, invalid JSON, empty keys, 4xx/5xx, cancelled context), `checkSecretKeys`, bundled no-op, external DB reachable/unreachable, Kafka/OIDC non-blocking, DB secret missing keys.

[`validation_s3_test.go`](../../internal/controller/validation_s3_test.go): `ListBuckets` reachable / 403 / unreachable / TLS verify failure; reconcile `StorageReachable` / `StorageUnreachable` / `StorageSecretInvalid`; discovered-secret path.

## Closed ticket gaps (2026-08-16)

### G1. S3 `ListBuckets` (connectivity) probe — **done**

`validateObjectStorage` calls AWS SDK `ListBuckets` against `resources.S3Endpoint` with path-style addressing (MinIO / NooBaa / Ceph RGW). Success → `StorageReachable`; network/TLS/HTTP error → `StorageUnreachable`. Discovery may still set `StorageReady=True` (`UserProvided` / `Discovered`) first; Validation overwrites in the same reconcile.

**Caveat:** NooBaa HTTPS (`s3.openshift-storage.svc`) needs the OpenShift service CA in the operator pod; a default `http.Client` can fail `x509` while app pods succeed via `AWS_CA_BUNDLE`.

### G2. S3 credentials Secret validation — **done**

`checkSecretKeys` on user `objectStorage.secretName` or `status.discoveredConfig.s3.secretName` for `access-key` / `secret-key`. Missing Secret or keys → `StorageSecretInvalid` and no `ListBuckets`. Keys alone no longer set `StorageReady=True`.

### G3. OIDC probe success criteria — **done**

`jwksProbe` (replaces `httpProbe`): reconcile context + timeout; HTTP 2xx; JSON body with non-empty `keys`. 401/403/404 and a 200 HTML/`{}`/`"keys":[]` yield `OIDCUnreachable`. JWKS-vs-well-known remains an intentional deviation.

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| `status.phase` `Validating` → `Migrating` | Internal Validation stage; status stays `Progressing` until Ready/Degraded | [design-vs-jira.md](../design/design-vs-jira.md) §1 — conditions are the machine API |
| `credentialsSecretRef` | `secretName` / Kafka `sasl.existingSecret` | Settled API naming (COST-7678) |
| OIDC **well-known** HTTP probe | JWKS URL probe (`…/protocol/openid-connect/certs`) | Matches what Envoy actually fetches (`KeycloakJWKSURL`) |
| All probe failures block progression | Only external DB + Cache block; Kafka/OIDC/S3 non-blocking | Code comment: init containers / late-start infra; conditions remain independent |
| S3 handled in Validation phase | Discovery still *resolves* S3; Validation now *checks* keys + `ListBuckets` | COST-7683 owns discovery; 7684 owns probes |
| Failures “independent” vs hard gate | Conditions always written independently; gate is selective | Aligns with condition model; differs from literal “all probes passing” |

## Related gaps (not in Jira body; same surface)

### R1. `AuthenticationReady` overwritten by Edge — **closed (COST-7688)**

Edge now writes `GatewayReady`. Validation keeps `AuthenticationReady` for the OIDC JWKS probe. See [COST-7688](COST-7688.md).

### R2. Kafka multi-broker host parsing elsewhere

`kafkaTCPProbe` correctly splits brokers; `KafkaHost` / `KafkaPort` in [`internal/resources/names.go`](../../internal/resources/names.go) still treat the whole comma-separated string as one host (deep-code-review D5). Validation can report `KafkaReady` while apps get a malformed host — outside Validation, but masks the bug.

### R3. Conditional Kruize / ROS DB keys (**closed** — Validation; remaining COST-8054 is independent enablement)

`requiredDBSecretKeys` requires `koku-*` / `rbac-*` always, and `ros-*` / `kruize-*` only when `spec.ros.enabled=true`. `postgres-*` is not required on the BYOI Secret. Remaining COST-8054 work is independent Cost/ROS/Kruize enablement and day-2, not this key list.
