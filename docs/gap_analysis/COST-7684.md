# COST-7684 Gap Analysis: Implement external dependency validation

**Jira:** [COST-7684](https://redhat.atlassian.net/browse/COST-7684)
**Audited:** 2026-08-10
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)). Kruize secret-key validation (R3) and conditional `ros-*` keys are owned by [COST-8054](../jira/COST-8054.md). Caveat: Validation still **always** requires `ros-user` / `ros-password` even when `spec.ros.enabled=false` (workloads/migrate already skip).

## Verdict

Core validation is implemented in `reconcileValidation` (TCP probes, secret key checks, component conditions), but COST-7684 is **not fully done**. Ticket-scoped gaps remain around **S3**: no `ListBuckets` (or equivalent) connectivity probe, and no validation that a user-provided `objectStorage.secretName` exists with `access-key` / `secret-key`. OIDC probing also underspecifies success (JWKS HTTP probe accepts any status &lt; 500). `docs/tasks.md` marking this ticket ✅ Done is docs drift. Kruize DB key omission (R3) is related/docs drift owned by [COST-8054](../jira/COST-8054.md) — not in the Jira AC text.

## Done (meets or supersedes ticket intent)

Implemented primarily in [`internal/controller/validation.go`](../../internal/controller/validation.go), invoked as stage 3 in `reconcile()` after Infrastructure and before Migration:

### Connectivity probes

- External DB TCP probe when `database.deploy=false` → `DatabaseReady` True/False (`DatabaseReachable` / `DatabaseUnreachable`)
- External Cache TCP probe when `cache.deploy=false` → `CacheReady`
- Kafka TCP probe over comma-separated `bootstrapServers` (`kafkaTCPProbe`, first reachable broker wins) → `KafkaReady`
- OIDC HTTP GET to `resources.KeycloakJWKSURL(cfg)` when `auth.keycloak.url` is set → `AuthenticationReady` (`OIDCReachable` / `OIDCUnreachable`), honors `insecureSkipVerify`

### Secret key validation

`checkSecretKeys` requires Secret exists and listed keys are non-empty:

| Ref | Required keys |
|-----|---------------|
| `database.secretName` | `postgres-user`, `postgres-password`, `koku-user`, `koku-password`, `ros-user`, `ros-password`, `rbac-user`, `rbac-password` |
| `cache.auth.secretName` | `redis-password` |
| `kafka.sasl.existingSecret` | `username`, `password` |

### Pipeline gating

- DB / Cache failures set `allReady=false` and return `RequeueAfter` (blocks Migration+)
- Kafka / OIDC failures set conditions only (non-blocking) — documented in function comment
- Bundled DB/Cache (`deploy=true`) skips external probes (infra readiness handled earlier)

### Env wiring for later phases

Resolved secret *names* are consumed via `EnvFromSecret` / `EnvFromSecretOptional` in [`internal/resources/env.go`](../../internal/resources/env.go) and related builders — credentials are not copied into CR status (better than the ticket’s implied in-memory resolution).

### Tests

[`validation_test.go`](../../internal/controller/validation_test.go): TCP/Kafka/HTTP helpers, `checkSecretKeys`, bundled no-op, external DB reachable/unreachable, Kafka non-blocking, DB secret missing keys.

## Remaining gaps (ticket-scoped)

### G1. S3 `ListBuckets` (connectivity) probe — missing

Ticket requires an S3 connectivity probe that sets its own condition. There is no `ListBuckets` (or HeadBucket / GetCallerIdentity-style) call in Validation or Discovery. Discovery only resolves endpoint + secret name and sets `StorageReady=True` with reason `UserProvided` / `Discovered` without talking to the object store.

**Impact:** Invalid endpoint, wrong TLS, or bad network path still leave `StorageReady=True` and the pipeline can proceed to Ready while uploads fail at runtime.

### G2. S3 credentials Secret validation — missing

Ticket: validate S3 credentials Secret exists and contains expected keys. CRD documents keys `access-key` and `secret-key` on `objectStorage.secretName`.

`userProvidedS3()` returns immediately without `Get`/`checkSecretKeys`. Validation does not touch object storage. Optional env selectors (`EnvFromSecretOptional` for `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` in [`env.go`](../../internal/resources/env.go)) mean missing keys may not even fail pod admission.

**Impact:** Explicit user credential refs can be wrong or absent while `StorageReady=True` (same surface as code-review F3).

### G3. OIDC probe success criteria too weak — partial

Ticket intent is a meaningful OIDC reachability check. Current `httpProbe` treats any HTTP status &lt; 500 as success, so 401/403/404 still yield `AuthenticationReady=True`. Probe also uses `context.Background()` instead of the reconcile context (code-review F4).

JWKS-vs-well-known endpoint choice is an intentional deviation; accepting error responses is not.

## Related gaps (not in Jira body; same surface)

### R1. `AuthenticationReady` overwritten by Edge

Validation may set `AuthenticationReady=False` (`OIDCUnreachable`), then Edge sets the same condition True when Envoy + Route exist (`GatewayReady`) — deep-code-review D3. OIDC failure is erased in the same reconcile pass (`costmanagementserviceconfig_controller.go` ~539–551).

### R2. Kafka multi-broker host parsing elsewhere

`kafkaTCPProbe` correctly splits brokers; `KafkaHost` / `KafkaPort` in [`internal/resources/names.go`](../../internal/resources/names.go) still treat the whole comma-separated string as one host (deep-code-review D5). Validation can report `KafkaReady` while apps get a malformed host — outside Validation, but masks the bug.

### R3. External DB secret key list omits Kruize credentials — partial (**→ [COST-8054](../jira/COST-8054.md)**)

Not named in the COST-7684 Jira body. CRD comment on `DatabaseConfig.SecretName` lists `kruize-user` / `kruize-password`. Operator-generated DB secret includes them (`internal/resources/secrets.go`). Validation’s required slice for user-provided secrets does **not**, so incomplete external secrets can pass Validation and still break Kruize/DB init paths that expect those keys.

**Not required for Cost beta** — close under COST-8054 when Kruize is optionally enableable (with conditional key checks).
