# COST-7688 Gap Analysis: Implement Gateway and Ingress

**Jira:** [COST-7688](https://redhat.atlassian.net/browse/COST-7688)
**Audited:** 2026-08-10
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)); optional install → [COST-8054](../jira/COST-8054.md). Gateway/Ingress for the Cost stack remain in beta; no ROS or Kruize gateway work is required here.

## Verdict

COST-7688 is **largely done**. Envoy JWT proxy (Deployment + Service + ConfigMap) is wired to CR OIDC issuer/audiences, the insights-ingress-go upload Deployment + Service are applied, and Edge gates on Envoy readiness before marking success. One ticket-scoped gap remains: **gateway readiness is reported on `AuthenticationReady` with reason `GatewayReady`**, which is conflated with the Validation-stage OIDC probe and can overwrite `OIDCUnreachable` in the same reconcile pass.

## Done (meets or supersedes ticket intent)

### Envoy JWT gateway

Implemented in [`internal/resources/envoy.go`](../../internal/resources/envoy.go), applied in `reconcileEdge`:

- `EnvoyConfigMap` — ConfigMap key `envoy.yaml` from `EnvoyYAML`
- `EnvoyService` — ClusterIP, port 80 → container `http` (9080), admin 9901
- `EnvoyDeployment` — image from `spec.auth.envoy` or OSSM proxyv2 default; replicas default 2; CA-combine init; readiness on admin `/ready`
- Names: `{cr}-gateway`, `{cr}-gateway-envoy-config` (`NameEnvoy`, `NameEnvoyConfigMap`)

### OIDC wiring from CR

| Helper | CR source | Envoy use |
|--------|-----------|-----------|
| `KeycloakIssuerURL` | `spec.auth.keycloak.issuerURL` or `url` + realm | JWT `issuer` |
| `KeycloakAudiences` | `spec.auth.keycloak.audiences` (CRD defaults) | JWT `audiences` |
| `KeycloakJWKSURL` | always from `url` + realm | `remote_jwks` URI (in-cluster fetch) |

Unit coverage in [`envoy_test.go`](../../internal/resources/envoy_test.go): issuer/JWKS defaults & override, audiences, YAML contents, Deployment mounts.

### Ingress upload service

Implemented in [`internal/resources/ingress.go`](../../internal/resources/ingress.go), applied in `reconcileWorkers` (before Edge so Envoy has a backend):

- `IngressDeployment` + `IngressService` — ports **8080** (http) / **9000** (metrics)
- S3 via `INGRESS_MINIOENDPOINT` (`ingressS3Endpoint`, prefers discovered endpoint), keys from storage Secret
- Kafka brokers / announce topic / optional SASL
- `INGRESS_AUTH=true` (trusts Envoy-injected `X-Rh-Identity`)
- CA combine init + `SSL_CERT_FILE`

### Gateway Route (supersedes ticket minimum)

[`GatewayAPIRoute`](../../internal/resources/route.go) — OpenShift Route `{cr}-api` path `/api` → Envoy Service; host from `gatewayRoute.hosts[0]` or `{name}-gateway-{ns}.{clusterDomain}`. Covered by [`route_test.go`](../../internal/resources/route_test.go).

### Status reporting (basic)

In `reconcileEdge` after `isDeploymentReady(..., NameEnvoy)`:

| State | Condition | Reason |
|-------|-----------|--------|
| Envoy not ready | `AuthenticationReady=False` | `WaitingForGateway` |
| Envoy ready, no Route host | `AuthenticationReady=False` | `ClusterDomainPending` |
| Envoy + Route ready | `AuthenticationReady=True` | `GatewayReady` |

## Remaining gaps (ticket-scoped)

### G1. Gateway readiness condition conflated with OIDC — partial

Ticket asks that status conditions reflect Gateway readiness. Edge does set `AuthenticationReady` with reason `GatewayReady`, but:

1. **Same condition type** is set earlier in `reconcileValidation` for JWKS reachability (`OIDCReachable` / `OIDCUnreachable`) — [`validation.go`](../../internal/controller/validation.go).
2. When Envoy + Route succeed, Edge **unconditionally** sets `AuthenticationReady=True` (`GatewayReady`), clearing a prior `OIDCUnreachable` in the same pass — deep-code-review **D3**, also [COST-7684 R1](COST-7684.md).

**Impact:** Operators cannot trust `AuthenticationReady` as either “OIDC reachable” or “gateway ready” alone. A broken JWKS path can still show Ready after Edge succeeds.

**Closure options:** dedicated `GatewayReady` condition type; or compose `AuthenticationReady` from both OIDC + Envoy/Route without allowing Edge to erase OIDC failure.

## Related gaps (not in Jira body; same surface)

### R1. Envoy `/api/ingress/` timeout too short vs Helm

[`envoy.go`](../../internal/resources/envoy.go) route timeout **30s** / `per_try_timeout` **15s**. Helm chart default is **180s** / **60s** ([helm-vs-operator-comparison.md](../helm-vs-operator-comparison.md)). Large uploads can fail under the operator.

### R2. Keycloak TLS CR fields unused by Envoy

`spec.auth.keycloak.tls.insecureSkipVerify` / `caCertSecretName` affect Validation probe and UI oauth-proxy, not Envoy’s JWKS TLS context (deep-code-review **D11**). Envoy always trusts the combined service-CA bundle + SAN match on Keycloak host.

### R3. Envoy ConfigMap changes do not roll pods

No config checksum / annotation on the Deployment pod template (deep-code-review **D20**). Issuer/audience/JWKS edits update the ConfigMap via SSA but may leave running Envoy on stale config until something else rolls the Deployment.

### R4. Ingress readiness not gated

Ingress is applied in Workers with **no** `isDeploymentReady` check and no Ingress-specific condition. Edge only waits on Envoy. A broken ingress image leaves `GatewayReady` True while `/api/ingress/` backends fail (deep-code-review readiness note).

### R5. Route TLS modes vs plaintext Envoy

CR accepts `passthrough` / `reencrypt` on `gatewayRoute.tls.termination`, but Envoy listens plaintext HTTP only (deep-code-review **D19**). Path list on `gatewayRoute.hosts[].paths` is ignored (hardcoded `/api`).

### R6. Missing unit tests for Ingress builders

No `ingress_test.go`. Envoy and Route have tests; Ingress env/endpoint helpers are unverified at unit level. No controller tests for `reconcileEdge` / `GatewayReady` reasons.

## Recommended closure order

1. **G1** — Split or compose gateway vs OIDC status so Edge cannot clear `OIDCUnreachable`
2. **R1** — Raise Envoy `/api/ingress/` timeouts to chart defaults (180s / 60s), optionally default Route timeout annotation
3. **R3** — Annotate Envoy pod template with ConfigMap checksum so OIDC edits roll pods
4. **R2** — Honor Keycloak TLS settings (or document that Envoy only uses combined CA)
5. **R4** / **R6** — Gate or condition Ingress readiness; add `ingress_test.go` (+ Edge condition tests)
