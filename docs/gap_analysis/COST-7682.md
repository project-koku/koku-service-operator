**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.

## Verdict

COST-7682 is **done**. Cluster domain and default StorageClass are auto-detected, written to `status.discoveredConfig`, and surfaced via `DiscoveryComplete` True/False with descriptive reasons. User overrides via `spec.global.*` supersede the ticket. Remaining notes are related product risks on the same surface (BYOI StorageClass gating; PVC builders ignore discovered StorageClass), not unmet acceptance criteria.

## Done (meets or supersedes ticket intent)

Implemented in [`internal/controller/discovery.go`](../../internal/controller/discovery.go), wired as Stage 0 in [`costmanagementserviceconfig_controller.go`](../../internal/controller/costmanagementserviceconfig_controller.go):

### Cluster domain

- `discoverClusterDomain` reads unstructured `config.openshift.io/v1` Ingress named `cluster`, field `spec.domain` (no `openshift/api` dependency)
- `resolveClusterDomain` prefers `spec.global.clusterDomain` when set and **not** the CRD sentinel default `apps.cluster.local` (so OpenAPI default still triggers real discovery)
- Failure → `DiscoveryComplete=False`, reason `ClusterDomainNotFound`, message includes error + `set spec.global.clusterDomain to override`; slow requeue

### Default StorageClass

- `discoverDefaultStorageClass` lists `storage.k8s.io` StorageClasses and returns the one annotated `storageclass.kubernetes.io/is-default-class=true`
- `resolveStorageClass` prefers non-empty `spec.global.storageClass`
- Result written to `status.discoveredConfig.storageClass`
- Failure → `DiscoveryComplete=False`, reason `StorageClassNotFound`, override hint; slow requeue

### Status / conditions

- `status.discoveredConfig` (`DiscoveredConfig`) populated before continuing the pipeline
- Success: `DiscoveryComplete=True`, reason `Discovered`, message `clusterDomain=… storageClass=…`
- Condition constant: `ConditionDiscoveryComplete` in types

### RBAC

- `+kubebuilder:rbac` on the reconciler and generated [`config/rbac/role.yaml`](../../config/rbac/role.yaml): `config.openshift.io` ingresses `get`; `storage.k8s.io` storageclasses `get;list`

### Tests

Eleven unit tests in [`discovery_test.go`](../../internal/controller/discovery_test.go) with fake client: domain found/missing/empty; SC found/none-default/empty/multiple; full-stage success, user override, domain failure requeue+condition, SC failure requeue+condition.

### Supersedes ticket

- Explicit user override path via `spec.global.clusterDomain` / `spec.global.storageClass` (not required by Jira AC)
- Downstream Route host resolution prefers `status.discoveredConfig.clusterDomain` ([`internal/resources/route.go`](../../internal/resources/route.go); also UI helpers via `discoveredClusterDomain`)

## Related gaps (not in Jira body; same surface)

### R1. BYOI path blocks on missing default StorageClass

Even when `database.deploy` / `cache.deploy` are false and no PVC will be created, discovery still requires a default StorageClass (or `spec.global.storageClass`). Documented as D21 in [deep-code-review-2026-08-10.md](../deep-code-review-2026-08-10.md). Contradicts production BYOI target; users must set an irrelevant override.

### R2. Discovered StorageClass not consumed by PVC builders

[`database.go`](../../internal/resources/database.go) and [`cache.go`](../../internal/resources/cache.go) read only `cfg.Spec.Global.StorageClass`. Auto-detected names live in `status.discoveredConfig.storageClass` but are not applied to StatefulSet volumeClaimTemplates / Cache PVC. Empty Spec often still works (API server picks cluster default when `storageClassName` is nil), but explicit discovered pinning and override-via-status consistency are missing. Cluster domain **is** consumed from status for Routes — StorageClass is asymmetric.

### R3. Legacy default-SC annotation not checked

Only `storageclass.kubernetes.io/is-default-class` is recognized. Clusters that still expose only `storageclass.beta.kubernetes.io/is-default-class=true` would fail discovery. Low likelihood on current OpenShift; worth a one-line fallback if field reports appear.

### R4. Sentinel domain cannot be a deliberate override

`apps.cluster.local` is both the CRD OpenAPI default and the “treat as unset” sentinel in `resolveClusterDomain`. A user who truly wants that hostname must fight the sentinel (or rely on status after discovery fails / is skipped). Acceptable for OpenShift apps domains in practice.
