# COST-7691 Gap Analysis: Routes, NetworkPolicies, and TLS

**Jira:** [COST-7691](https://redhat.atlassian.net/browse/COST-7691)
**Audited:** 2026-08-10
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)). NetworkPolicies / ServiceAccounts for ROS API, ROS workers, and Kruize are owned by [COST-8054](../jira/COST-8054.md). Beta should-haves here are user-CA merge and NPs/SAs for **core** components (UI, Masu/Listener, gateway/ingress/RBAC as capacity allows).

## Verdict

Substantial edge/TLS/SCC scaffolding exists (gateway + UI Routes, five NetworkPolicies, service-CA combine init, three dedicated SAs, app-pod restricted-v2 alignment, `status.phase → Ready` on pipeline success), but COST-7691 is **not done**. Remaining ticket gaps are incomplete NetworkPolicy coverage, incomplete dedicated ServiceAccounts, user-CA merge into the combined bundle, and Ready not gated on Route admission. ROS workers still on `default` is a real inconsistency but owned by [COST-8054](../jira/COST-8054.md).

## Done (meets or supersedes ticket intent)

### Gateway Route (edge TLS)

[`internal/resources/route.go`](../../internal/resources/route.go) `GatewayAPIRoute`:

- Host from `spec.gatewayRoute.hosts[0]` or `{name}-gateway-{ns}.{clusterDomain}`
- Default TLS `termination: edge`, `insecureEdgeTerminationPolicy: Redirect`
- Path `/api` → Envoy Service
- Returns `nil` when domain/host unresolved; reconciler requeues with `AuthReady=False` / `ClusterDomainPending`

Applied in `reconcileEdge`. Tests in [`route_test.go`](../../internal/resources/route_test.go).

### UI Route (TLS via oauth-proxy)

[`internal/resources/ui.go`](../../internal/resources/ui.go) `UIRoute`:

- Host `{name}-ui-{ns}.{clusterDomain}`; deferred (`nil`) until domain discovered
- Applied from `reconcileUI` when OAuth client Secret is valid
- Service uses OpenShift serving-cert annotation; Route uses **passthrough** so oauth2-proxy terminates TLS

### NetworkPolicies (subset)

[`internal/resources/networkpolicies.go`](../../internal/resources/networkpolicies.go), applied in `reconcileEdge`:

| Policy | Selects | Allows from |
|--------|---------|-------------|
| `GatewayNetworkPolicy` | `gateway` | OpenShift ingress NS, `ui`, monitoring (admin) |
| `IngressNetworkPolicy` | `ingress` | `gateway` |
| `KruizeNetworkPolicy` | `ros-optimization` | ROS processor / poller / housekeeper |
| `RBACAPINetworkPolicy` | `rbac-api` | gateway, koku-api, masu, ros-api |
| `KokuAPINetworkPolicy` | `cost-management-api` | gateway, masu, ros-housekeeper, monitoring |

Controller `.Owns(&networkingv1.NetworkPolicy{})`; ClusterRole has NetworkPolicy CRUD.

### CA combine scaffolding

| Piece | Path |
|-------|------|
| Script CM | `configmaps.go:CACombineConfigMap` — merges `/etc/pki/.../tls-ca-bundle.pem` + `/ca-source/*.crt` |
| Service CA CM | `configmaps.go:ServiceCAConfigMap` — `service.beta.openshift.io/inject-cabundle: "true"` |
| Init container | `volumes.go:CACombineInitContainer` (`prepare-ca-bundle`) |
| Created | `reconcileSharedConfig` |

Used on Koku family Deployments/Jobs, Envoy, Ingress, ROS Processor (and migration).

### Dedicated ServiceAccounts (partial)

| SA | Builder | Used by |
|----|---------|---------|
| `{cr}-koku` | `koku.go:KokuServiceAccount` | Koku API / Masu / Listener / Celery (via shared `deployment` helpers), migration Jobs |
| `{cr}-ros-backend` | `ros.go:ROSServiceAccount` | ROS API Deployment, ROS partition CronJob |
| `{cr}-kruize` | `kruize.go:KruizeServiceAccount` | Kruize Deployment |

### restricted-v2 alignment (app path)

- No hardcoded `RunAsUser` in `internal/resources` builders (comments + `ui_test.go` assert `nil`)
- Pod SC helper `nonRootPodSC()` — `RunAsNonRoot` + `seccompProfile: RuntimeDefault` ([`database.go`](../../internal/resources/database.go))
- Container helpers: `restrictedContainerSC`, `kokuAppContainerSC`, `ubiMinimalInitSC`, UI oauth/app SCs — `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`
- No operator-managed `anyuid` RoleBindings remain under `internal/`

### Phase → Ready (pipeline success)

After all stages succeed with zero `Result`, reconciler sets:

- `cfg.Status.Phase = PhaseReady`
- `Available=True` / `AllComponentsReady`
- `Progressing=False` / `ReconcileComplete`
- `Ready` Event on first transition

Edge gates before Ready: Envoy Deployment ready, Gateway Route buildable (domain/host), NetworkPolicy apply success, `UIReady` not False.

### RBAC

ClusterRole / kubebuilder markers cover `route.openshift.io/routes` (+ `custom-host`), `networking.k8s.io/networkpolicies`, `serviceaccounts`.

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| UI Route with **edge** TLS | UI Route `termination: passthrough` | oauth2-proxy terminates TLS using OpenShift serving cert on the UI Service; edge would double-terminate incorrectly |
| Full restricted-v2 including RO root on koku/RBAC | `readOnlyRootFilesystem` omitted on koku/RBAC containers | Django file log handler blocker — [koku-django-log-handler-problem.md](../design/koku-django-log-handler-problem.md); fix belongs in koku |
| Bundled DB/cache under restricted-v2 | `default` SA + anyuid via `hack/deploy-crc.sh` | Dev/CI only; production is BYOI ([CLAUDE.md](../../CLAUDE.md) / design docs) |

## Remaining gaps (ticket-scoped)

### G1. NetworkPolicies for all components — partial

Only five ingress policies exist. No policies for:

- `ui` — **beta should-have** (secured beta)
- `cost-processor` (Masu), `listener`, `cost-scheduler`, `cost-worker-*` — Masu/Listener **beta should-have**; Celery workers P2
- `rbac-worker` — P2 / with RBAC readiness work
- `ros-api`, `ros-processor`, `ros-recommendation-poller`, `ros-housekeeper` — **→ [COST-8054](../jira/COST-8054.md)** (ROS)
- Bundled `database` / `cache` (dev path) — defer
- CronJobs (`ros-database-maintenance`, `ros-optimization-maintenance`) — **→ [COST-8054](../jira/COST-8054.md)** (ROS / Kruize)

Also absent: namespace default-deny, egress rules. Ticket wording is “for all components.”

### G2. Dedicated ServiceAccounts per component — partial

Only three SAs are created. Workloads still on the namespace `default` SA:

- Envoy gateway, Ingress, RBAC API + worker, UI — core SA gap (P2 for beta, or document shared-SA model)
- **ROS Processor / Poller / Housekeeper** — SA exists (`{cr}-ros-backend`) but these Deployments omit `ServiceAccountName` (inconsistency vs ROS API / CronJob) — **→ [COST-8054](../jira/COST-8054.md)** (ROS)
- Bundled PostgreSQL / Valkey (dev-only; acceptable as intentional for deploy path)

### G3. User-provided CAs in combined bundle — missing

Combine today is **system trust store + OpenShift service CA** only (`combine-ca.sh` cats `/ca-source/*.crt` from the injected service-CA ConfigMap).

Per-service TLS secrets (`kafka` / `cache` / `keycloak` CA secret fields) are mounted separately where needed — they are **not** merged into the shared bundle ConfigMap. Ticket AC explicitly asks for “service CA and any user-provided CAs.” Fuller CA management also appears in [COST-7694](https://redhat.atlassian.net/browse/COST-7694); close either here or there, but 7691 AC remains unmet until merge exists.

### G4. Ready gated on Route admission — missing

No code reads Route `status.ingress` / Admitted condition (grep clean under `internal/`). Gateway Route apply + Envoy ready is enough for `AuthReady=True` and eventual `PhaseReady`. UI Route can be skipped if domain missing only when gateway is also blocked; admission of either Route is never verified.

## Related gaps (not in Jira body; same surface)

### R1. Bundled cache pod SC missing `SeccompProfile`

[`cache.go:cachePodSC`](../../internal/resources/cache.go) sets `RunAsNonRoot` + `FSGroup` but not `SeccompProfile: RuntimeDefault` (unlike `nonRootPodSC`). Dev-only path, but weaker than app Deployments.

### R2. CA combine init not mounted on all TLS clients

UI, RBAC, Kruize, ROS API/poller/housekeeper do not use `CACombineInitContainer` (UI uses separate Keycloak/service-CA mounts). May be fine if those components do not need the combined bundle, but it is uneven relative to “mounted by components that need TLS verification” language in COST-7694. Uneven ROS and Kruize CA mounts → [COST-8054](../jira/COST-8054.md).

### R3. Design doc stale on SCC state

[security-context-strategy.md](../design/security-context-strategy.md) still claims hardcoded `runAsUser` 1000/1001 and anyuid RoleBindings for Kruize/ROS. Current code has removed both — doc needs a refresh (not done in this audit).
