# COST-7692 Gap Analysis: Implement monitoring and alerting

**Jira:** [COST-7692](https://redhat.atlassian.net/browse/COST-7692)
**Audited:** 2026-08-10
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)). ROS API / Kruize / ROS processor-poller scrape wiring is owned by [COST-8054](../jira/COST-8054.md). Do not block Cost beta on those targets unless beta explicitly promises in-cluster scrape for them.

## Verdict

COST-7692 is **not done**. A monitoring stage applies an aggregated app ServiceMonitor plus a five-rule `PrometheusRule` (and a Kruize ServiceMonitor when ROS is enabled), and the reconciler emits a partial Event set — but custom operator metrics are absent, app scrape targets are largely unreachable (port/label/Service/NetworkPolicy mismatches), the five alert rules do not match the ticket’s named thresholds, and the ticket Event reasons (`PhaseChanged`, `SecretRotated`, `DependencyFailed`, `DriftCorrected`) are missing. ROS and Kruize scrape fixes → [COST-8054](../jira/COST-8054.md). `docs/tasks.md` marking this ✅ is docs drift.

## Done (meets or supersedes ticket intent)

- **Monitoring stage** in [`reconcileMonitoring`](../../internal/controller/costmanagementserviceconfig_controller.go): applies `AppServiceMonitor` + `PrometheusRules` when `spec.monitoring.enabled` is true (default via `BoolVal(..., true)` / CRD `+kubebuilder:default:=true` on `MonitoringConfig.Enabled`); appends `KruizeServiceMonitor` only when [`ROSEnabled`](../../api/v1alpha1/costmanagementserviceconfig_types.go) is true.
- **Unstructured Prometheus Operator CRDs** — `monitoring.coreos.com/v1` ServiceMonitor + PrometheusRule builders in [`internal/resources/monitoring.go`](../../internal/resources/monitoring.go); `apimeta.IsNoMatchError` → log and continue so clusters without the CRDs still reconcile.
- **Scaffold operator scrape path** (deploy-time, not CR-reconciled): [`config/default/metrics_service.yaml`](../../config/default/metrics_service.yaml) (`controller-manager-metrics-service`) + [`config/prometheus/monitor.yaml`](../../config/prometheus/monitor.yaml); manager binds controller-runtime metrics in [`cmd/main.go`](../../cmd/main.go) (`metrics-bind-address`, default `:8080`).
- **Partial scrape surface that is correctly shaped:**
  - ROS API Service exposes named port `metrics` (9000) — [`ROSAPIService`](../../internal/resources/ros.go)
  - Ingress Service exposes `metrics` (9000) — [`IngressService`](../../internal/resources/ingress.go)
  - Koku API NetworkPolicy allows OpenShift monitoring namespaces to port 9000 — [`KokuAPINetworkPolicy`](../../internal/resources/networkpolicies.go)
  - Gateway NetworkPolicy allows monitoring → Envoy admin (9901) — [`GatewayNetworkPolicy`](../../internal/resources/networkpolicies.go) (no SM selector yet)
- **Five PrometheusRule alerts** applied under `{cr}-alerts` (different names/exprs than ticket — see gaps).
- **Partial Events** on the CR: `ReconcileError`, `Ready`, `MigrationStarted`, `MigrationComplete`, `MigrationFailed`.

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| Kind `CostManagement` Events | Events on `CostManagementServiceConfig` | Product kind rename (see [design-vs-jira.md](../design/design-vs-jira.md) §1) |
| One ServiceMonitor per app component | Aggregated `AppServiceMonitor` + `KruizeServiceMonitor` by component label `In` | Reasonable consolidation **if** selectors/ports work; currently they do not (still a functional gap) |
| Silent skip when Prometheus Operator CRDs absent | `IsNoMatchError` continue | Required for CRC/dev without user-workload monitoring; aligns with optional monitoring |

There is **no** design-doc justification for replacing the five ticket alert names/thresholds with the current condition-based set. Treat that as a gap unless product explicitly accepts the alternate rules.

## Remaining gaps (ticket-scoped)

### G1. Custom operator metrics + reconciled operator ServiceMonitor — missing

Ticket requires series:

- `costmanagement_reconcile_duration_seconds`
- `costmanagement_reconcile_errors_total`
- `costmanagement_component_ready`
- `costmanagement_migration_duration_seconds`

Evidence:

- Grep of `*.go` finds **no** `costmanagement_` metric registration (`prometheus.New*`, `MustRegister`, etc.).
- Only stock controller-runtime metrics via `metricsserver.Options` (plain HTTP bind on `:8080` in [`cmd/main.go`](../../cmd/main.go)).
- `OperatorServiceMonitor()` is defined in [`monitoring.go`](../../internal/resources/monitoring.go) but **not** included in `reconcileMonitoring`’s apply list (dead helper). It also sets namespace to the CR namespace and selects `control-plane: controller-manager`, which typically lives in the operator namespace — wrong place even if applied.
- Dedicated Service/ServiceMonitor for the manager exist only as kustomize scaffolds ([`metrics_service.yaml`](../../config/default/metrics_service.yaml) / [`monitor.yaml`](../../config/prometheus/monitor.yaml)), and they expect **HTTPS port 8443** while the manager currently binds **HTTP `:8080`** — scaffold path is inconsistent even before custom series exist.

**Impact:** Ticket’s named operator SLIs cannot be scraped or alerted on (`CostManagementReconcileFailure` as specified is impossible without `costmanagement_reconcile_errors_total` or equivalent).

### G2. Application ServiceMonitors incomplete / mostly non-functional — partial

| Ticket component | In App/Kruize SM selector? | Service + port `metrics`? | Notes |
|------------------|----------------------------|---------------------------|-------|
| Koku API | Yes (`cost-management-api`) | No — Service port named `http` on **8000**; metrics listen on pod 9000 but not on Service | NP allows 9000 but Service has no such port |
| MASU | Yes (`cost-processor`) | No — Service port named `http` on 9000 | Port name ≠ `metrics` |
| Celery workers | **No** | No Services | Not selected |
| ROS API | Yes (`ros-api`) | **Yes** | Only reliably scrapeable app target among listed — **post-beta** (ROS out of beta) |
| Kruize | Yes (`ros-optimization` via Kruize SM, when `ROSEnabled`) | No — Service port `http`/8080; SM still asks for port name `metrics` | Comment claims 8080 metrics; wire-up wrong — **post-beta** |
| RBAC | **No** | No metrics port on RBAC Service | Helm has RBAC ServiceMonitor; operator does not |
| Gateway | **No** | Envoy admin scrape allowed by Gateway NP, but no SM endpoint/selector for gateway | |

Additional blockers:

- **Listener** is in App SM component list but there is **no** `ListenerService`.
- ROS Processor / Recommendation Poller expose container `metrics` ports but **no** Services (helm-vs-operator §3.1) — → [COST-8054](../jira/COST-8054.md) (ROS).
- **Ingress NetworkPolicy** allows only gateway→8080; does **not** allow monitoring→9000, so Ingress SM target is blocked even though the Service has a `metrics` port.
- **Configurability missing:** `MonitoringConfig` is only `Enabled *bool`. Scrape `interval` hardcoded `"30s"`; no additional labels field. Ticket: “Scrape interval and labels configurable”.

Documented previously as D17 in [deep-code-review-2026-08-10.md](../deep-code-review-2026-08-10.md).

**Impact:** Enabling `monitoring.enabled` creates ServiceMonitors that largely select nothing scrapeable; Prometheus `up` for koku-api stays absent, so `CostManagementAPIDown` stays silent rather than firing (absent series ≠ `up==0`).

### G3. Ticket PrometheusRule names / thresholds — missing (alternate set present)

| Ticket alert | Ticket threshold | Implementation |
|--------------|------------------|----------------|
| `CostManagementPodRestarting` | >3 restarts / 15m | **Absent** |
| `CostManagementReconcileFailure` | >5 errors / 10m | **Absent** (needs operator error counter) |
| `CostManagementMigrationStalled` | Job not complete within 10m | **Absent** — have `CostManagementMigrationFailed` (failed jobs) + `CostManagementSchemaOutOfDate` (condition false 15m) |
| `CostManagementDependencyDown` | dependency condition False >5m | **Absent** as named — partial overlap with `CostManagementDegraded` / `CostManagementNotProgressing` |
| `CostManagementCeleryBacklog` | queue depth >1000 for >10m | **Absent** (no Celery queue metric scrape) |

Implemented instead ([`PrometheusRules`](../../internal/resources/monitoring.go)):

1. `CostManagementMigrationFailed`
2. `CostManagementDegraded`
3. `CostManagementSchemaOutOfDate`
4. `CostManagementAPIDown`
5. `CostManagementNotProgressing`

**Impact:** Alert catalog does not match the story AC. Product may prefer the condition-based set — if so, document as intentional deviation and close G3 by updating the Jira; until then it remains open.

### G4. Ticket Kubernetes Event reasons — partial

| Ticket reason | Status |
|---------------|--------|
| `PhaseChanged` | **Missing** (have one-shot-ish `Ready`, not general phase transitions) |
| `MigrationsComplete` | **Partial** — emitted as `MigrationComplete` (singular) |
| `SecretRotated` | **Missing** (also tracked under COST-7694) |
| `DependencyFailed` | **Missing** (validation sets conditions False without Events) |
| `DriftCorrected` | **Missing** (5-minute requeue re-applies with no Event) |

Extra reasons present but not in this ticket: `MigrationStarted`, `MigrationFailed`, `ReconcileError`.

**Impact:** Event-based automation/UX from the story cannot rely on the specified reasons. Cross-ref COST-7680 G3 (Ready transition check ineffective / Ready spam).
