## Done (meets or supersedes ticket intent for Cost beta)

- **Monitoring stage** in [`reconcileMonitoring`](../../internal/controller/costmanagementserviceconfig_controller.go): when `spec.monitoring.enabled` is true, applies `AppServiceMonitor` + `GatewayServiceMonitor` + `OperatorServiceMonitor` + `PrometheusRules`. When disabled, deletes those objects **and** `KruizeServiceMonitor` by name (orphan cleanup; Kruize SM is **not** in the apply set — COST-8054).
- **Unstructured Prometheus Operator CRDs** — builders in [`internal/resources/monitoring.go`](../../internal/resources/monitoring.go); absent CRD → log and continue so clusters without UWM still reconcile.
- **Custom operator series** in [`internal/metrics/conditions.go`](../../internal/metrics/conditions.go); gauges cleared on CMSC delete (`ClearConditionMetrics`, `ClearMigrationJobFailedAll`, `ClearManagedPodRestarts`).
- **Scrape surface that works for beta Cost core:**
  - Koku API / Masu / Ingress Services expose named port `metrics` (9000)
  - NetworkPolicies allow platform + UWM Prometheus to those ports (and Gateway admin / Masu)
  - App SM selects `cost-management-api`, `cost-processor`, `ingress`
  - Gateway SM scrapes Envoy admin `/stats/prometheus`
  - Operator SM: `control-plane: controller-manager` + `app.kubernetes.io/name: koku-service-operator`, scheme `http` on Service port name `https`
- **Eight PrometheusRule alerts** under `{cr}-alerts` (fireable with operator gauges + App SM `service=`):
  1. `CostManagementMigrationFailed`
  2. `CostManagementMigrationStalled`
  3. `CostManagementDegraded`
  4. `CostManagementDependencyDown`
  5. `CostManagementPodRestarting`
  6. `CostManagementNotAvailable`
  7. `CostManagementAPIDown`
  8. `CostManagementReconcileFailure`
- **Events on the CR:** `PhaseChanged` (Ready and Degraded, including blocking validation `RequeueAfter` / failed migrate `Stop`), `DependencyFailed`, `MigrationsComplete`, plus `Ready`, `ReconcileError`, migration lifecycle Events.

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| Kind `CostManagement` Events | Events on `CostManagementServiceConfig` | Product kind rename (see [design-vs-jira.md](../design/design-vs-jira.md) §1) |
| One ServiceMonitor per app component | Aggregated App SM + separate Gateway / Operator SMs | Consolidation is fine while selectors/ports work |
| Ticket SLI metric names | Condition / reconcile-error / migration-failed / pod-restart gauges | COST-8108 option B — fireable ops alerts without full histogram SLI set |
| Ticket ReconcileFailure threshold (`>5` / 10m) | `increase(...[15m]) > 0` with `for: 0m` | Lab-usable; trails Ready briefly on single errors |
| MigrationStalled as Job timeout | `SchemaUpToDate=False` for 10m (+ separate MigrationFailed Job gauge) | Matches observed CMSC semantics |
| Silent skip when Prometheus Operator CRDs absent | `IsNoMatchError` continue | Required for CRC/dev without UWM |
| No `CeleryBacklog` rule in #77 | Deferred | App SM does not scrape Celery workers; Masu `/metrics` does not refresh worker queue gauges |

Document product acceptance of the alternate alert/metric set in Jira when closing the story.
