# COST-7683 Gap Analysis: Implement S3 backend auto-detection

**Jira:** [COST-7683](https://redhat.atlassian.net/browse/COST-7683)
**Audited:** 2026-08-10
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update `docs/tasks.md` or other trackers.
**Beta scope:** ROS and Kruize are **out of beta** ([BETA-PRIORITY.md](BETA-PRIORITY.md)). Object storage for Ingress/uploads remains beta-relevant; OBC default claim name `ros-data-ceph` does not pull ROS into Cost beta. Optional ROS bucket discovery → [COST-8054](../jira/COST-8054.md).

## Verdict

Three-path S3 resolution (user `secretName` → Bound OBC → NooBaa), `StorageReady`, and `status.discoveredConfig.s3` are implemented and unit-tested. COST-7683 is **not fully done**. Remaining ticket gaps are **missing `objectbucket.io` RBAC** (OBC path fails Forbidden on real clusters) and **no bucket name in `DiscoveredS3`** despite the ticket requiring endpoint/bucket/credentials in discovered config.

## Done (meets or supersedes ticket intent)

### Three-path resolver

Implemented in [`internal/controller/discovery_s3.go`](../../internal/controller/discovery_s3.go):

1. **User-provided** — `cfg.Spec.ObjectStorage.SecretName != ""` → `userProvidedS3` (endpoint via `resources.S3Endpoint`, region via `s3Region`)
2. **Bound OBC** — prefer claim `ros-data-ceph`, else first Bound `ObjectBucketClaim` in the CR namespace; read ConfigMap (`BUCKET_HOST`/`BUCKET_PORT`) + Secret (`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`); copy into `<cr>-storage-credentials`
3. **NooBaa** — read `openshift-storage/noobaa-admin`, copy credentials, endpoint `https://s3.openshift-storage.svc.cluster.local:443`

Wired from Stage 0 [`reconcileDiscovery`](../../internal/controller/discovery.go): success → `DiscoveredConfig.S3` + `StorageReady=True` (`UserProvided` / `Discovered`); failure → clear S3, `StorageReady=False` (`S3NotFound`), **pipeline continues** (does not block `DiscoveryComplete`).

### Credential copy + ownership

`upsertStorageCredentials` creates/updates `<cr>-storage-credentials` with keys `access-key` / `secret-key`, annotation `koku.costmanagement.io/s3-source` (`obc:<name>` or `noobaa`), and ownerRef on the CR.

### Status surface

- Condition constant `ConditionStorageReady` in types
- `DiscoveredS3`: `endpoint`, `secretName`, `region`
- Downstream consumers prefer discovered endpoint when `secretName` is empty ([`resources.S3Endpoint`](../../internal/resources/names.go), ingress env builders)

### Tests

[`discovery_s3_test.go`](../../internal/controller/discovery_s3_test.go): user path; OBC credential copy; NooBaa; none → error; reconcileDiscovery sets `StorageReady` True/False and continues on failure.

### Secrets cluster-wide for NooBaa

Manager `ClusterRole` + `ClusterRoleBinding` grant `secrets` get/list cluster-wide, so reading `openshift-storage/noobaa-admin` is authorized (unlike OBC CRDs — see G1).

## Remaining gaps (ticket-scoped)

### G1. `objectbucket.io` RBAC missing — blocks OBC path in-cluster

[`config/rbac/role.yaml`](../../config/rbac/role.yaml) and reconciler `+kubebuilder:rbac` markers have **no** rules for `objectbucket.io` `objectbucketclaims` (get/list). Fake-client unit tests succeed; a real ODF cluster returns Forbidden.

`findBoundOBC` treats any non-NotFound Get error (including Forbidden) as “no bound OBC”, then List also fails → falls through to NooBaa or `S3NotFound`. Ticket path 2 is therefore not production-viable until RBAC is generated and applied.

**Fix:** add kubebuilder RBAC markers (get;list on ObjectBucketClaims), regenerate manifests, verify on a cluster with a Bound OBC.

### G2. Bucket name not recorded in `DiscoveredS3` — partial AC

Ticket: populate discovered config with resolved **endpoint / bucket / credentials**.

`DiscoveredS3` has `Endpoint`, `SecretName`, `Region` only — no `Bucket` (or equivalent). OBC ConfigMap `BUCKET_NAME` is available in tests’ helper data but **never read** in `discoverOBC`. App env still uses `spec.costManagement.storage.bucketName` / `rosBucketName` ([`env.go`](../../internal/resources/env.go)), which can diverge from the OBC-provisioned bucket.

**Fix:** add `bucket` to `DiscoveredS3` from OBC ConfigMap; document that NooBaa/user paths still rely on Spec bucket fields unless also discovered. Optional `rosBucket` discovery → [COST-8054](../jira/COST-8054.md) (ROS); OBC claim name `ros-data-ceph` is naming-only and does not make ROS a Cost beta requirement.

## Related gaps (not in Jira body; same surface)

### R1. User-provided S3 Secret trusted without key validation

When `secretName` is set, discovery sets `StorageReady=True` without Get/validating `access-key`/`secret-key`. Documented as F3 in [code-review-2026-08-10.md](../code-review-2026-08-10.md). Better owned with COST-7684 secret probing (`checkSecretKeys`), but it makes this ticket’s success condition over-optimistic for BYOI.

### R2. `Available` ignores `StorageReady`

Pipeline can reach `Available=True` / `Phase=Ready` while `StorageReady=False` (or True with broken user secret). Ticket only requires the StorageReady condition itself; product readiness should eventually gate on it.

### R3. Placeholder storage Secret when discovery fails

If `secretName` is empty and OBC/NooBaa fail, Stage 1 still `ensureSecret`s a placeholder with `REPLACE_WITH_REAL_*` keys ([`secrets.go`](../../internal/resources/secrets.go)). Pods can start with useless credentials while `StorageReady=False`.

### R4. Region default mismatch

Resolver fallback `defaultS3Region = "us-east-1"` vs CRD/`S3Options` OpenAPI default `onprem`. Behavior depends on whether CRD defaulting applied the Spec field before discovery.

## Recommended closure order

1. **Add `objectbucket.io` RBAC** (G1), regenerate `config/rbac/role.yaml`, smoke-test Bound OBC on ODF.
2. **Extend `DiscoveredS3` with bucket** from OBC ConfigMap (G2); decide whether Spec bucket fields should be defaulted from discovery.
3. **Optionally** wire user-secret key checks into validation (R1 / COST-7684) and gate `Available` on `StorageReady` when object storage is required (R2).
