## Verdict

COST-7681 is **largely done**. The shared SSA apply helpers, ownerReferences, finalizer cleanup for cluster-scoped resources, and 5-minute drift requeue are implemented and unit-tested. One ticket-scoped gap remains: the bundled PostgreSQL StatefulSet update path bypasses SSA (`Create`/`Update` instead of `client.Apply`). Field-manager naming differs from the Jira string by design.

## Done (meets or supersedes ticket intent)

Implemented primarily in [`internal/controller/costmanagementserviceconfig_controller.go`](../../internal/controller/costmanagementserviceconfig_controller.go):

### Server-Side Apply layer

- `fieldOwner = "koku-service-operator"` (const L28)
- `apply()` — namespace + `setOwnerRef` + `Patch(..., client.Apply, client.ForceOwnership, client.FieldOwner(fieldOwner))`
- `applyClusterScoped()` — same SSA options without ownerRef (ConsoleLink, Kruize ClusterRole/Binding)
- `ForceOwnership` supersedes pure conflict-fail behavior so drift correction can reclaim fields (aligns with the ticket’s “revert manual modifications” goal)

Consumers across stages (shared config ConfigMaps/SA, infra Services/Deployments/PVC, core/workers/edge/monitoring) call `apply` / `applyClusterScoped`.

### Ownership model

- `setOwnerRef()` sets `APIVersion`/`Kind`/`Name`/`UID` with `Controller: true` and `BlockOwnerDeletion: true`
- Skips cluster-scoped objects (`namespace == ""`)
- Idempotent (no duplicate refs) — covered by `TestSetOwnerRef_*` in [`ownership_test.go`](../../internal/controller/ownership_test.go)
- Used from `apply`, `ensureSecret`, migration Job create, StatefulSet create, and S3 credential upsert (create path)

### Finalizer cleanup

- Finalizer: `costmanagementserviceconfigs.service.costmanagement.openshift.io/cleanup`
- Added before any cluster-scoped work; stripped only after `reconcileDelete`
- `reconcileDelete()` deletes, in order: ConsoleLink, Kruize ClusterRoleBinding, Kruize ClusterRole (NotFound tolerated)
- Tests: `TestReconcile_AddsFinalizer`, `TestReconcileDelete_RemovesClusterScopedResourcesAndFinalizer`, `TestReconcileDelete_ToleratesMissingResources`

### Drift correction

- Successful full reconcile returns `ctrl.Result{RequeueAfter: requeueDrift}` with `requeueDrift = 5 * time.Minute`
- Comment at L174–176 documents intent: re-apply desired state so manual edits revert without waiting for a watch event
- Constant range asserted in `TestReconcile_DriftRequeueOnSuccess`

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| Field manager `cost-management-operator` | `koku-service-operator` | Matches product/module naming in [CLAUDE.md](../../CLAUDE.md); same SSA semantics |
| Kind `CostManagement` as owner | `CostManagementServiceConfig` | Settled API naming (see design-vs-jira) |
| SSA conflict detection without force | `ForceOwnership` on every Apply | Required for automatic drift reversion; without force, contested fields would stay drifted |
| All resources via SSA | Secrets: `ensureSecret` create-if-absent | Must not overwrite generated credentials (Django key, DB password, UI cookie) |
| All resources via SSA | Migration Jobs: `Create` + ownerRef | Jobs are largely immutable; upgrade path deletes and recreates on image-tag change |
| All resources via SSA | Storage credentials: `Create`/`Update` in `upsertStorageCredentials` | Credential copy from OBC/NooBaa; not a managed declarative workload shape |

## Remaining gaps (ticket-scoped)

### G1. Bundled PostgreSQL StatefulSet bypasses SSA — partial

**Evidence:** `applyStatefulSet()` in [`costmanagementserviceconfig_controller.go`](../../internal/controller/costmanagementserviceconfig_controller.go) L689–708:

- First reconcile: `Create` (with ownerRef)
- Updates: `r.Update` on a partial patch (replicas, first container image/resources/env only)
- No `client.Apply` / field manager ownership for subsequent reconciles

**Impact:**

- Manual edits to non-patched fields (init containers, volumes, securityContext, probes, etc.) are **not** reverted by the 5-minute drift loop
- Documented already as design gap §4c in [design-vs-jira.md](../design/design-vs-jira.md)
- Scope is narrowed by product policy: bundled DB is **dev/CI only**; production BYOI never creates this StatefulSet

**Suggested fix (from design doc):** Apply mutable spec fields via SSA; detect VCT changes separately and surface a condition rather than silent ignore.

## Related gaps (not in Jira body; same surface)

### R1. Drift requeue test is constant-only

`TestReconcile_DriftRequeueOnSuccess` asserts `requeueDrift` ∈ [5m, 10m] but does not drive a successful `reconcile()`/`Reconcile()` and assert `result.RequeueAfter == requeueDrift`. Regression risk if the success-path return is removed.

### R2. `reconcileDelete` test omits ConsoleLink

Deletion test pre-creates Kruize ClusterRole/Binding only. ConsoleLink is in the delete list but not asserted gone (fake client also lacks the ConsoleLink GVK unless registered).

### R3. Non-SSA update paths may leave ownerRef unrepaired

`applyStatefulSet` update branch mutates `existing` and calls `Update` without re-running `setOwnerRef`. `upsertStorageCredentials` sets ownerRef on the create object but the update branch only patches `Data`/`Annotations` on `existing`. If someone strips ownerReferences, the 5-minute loop will not restore them (unlike SSA `apply`).
